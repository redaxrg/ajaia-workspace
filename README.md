# Ajaia Notes

A small shared document workspace built for the Ajaia product-engineering exercise. The app focuses on a dependable editing loop: create or import a page, format it, share it with a teammate, and reopen it later.

## Run Locally

Requirements: Node.js 20 or newer and npm.

```sh
npm install
npm run dev
```

Open the Vite URL printed in the terminal (normally `http://localhost:5173`). The API runs on port `3001` and Vite proxies `/api` requests to it. For a production-shaped local run:

```sh
npm run build
npm start
```

Then open `http://localhost:3001`. Documents are stored in `data/ajaia-data.json`. Set `DATA_DIR` to move that data directory. The store is created on first run with a sample shared document.

Optional local settings can be loaded by copying `.env.example` to `.env`. Never put production passwords or session secrets in source control; `.env` is ignored by Git.

## Demo Accounts

The app has two seeded demo accounts:

- Alice Chen: `alice@ajaia.test` (local development password: `alice-demo`)
- Marco Ruiz: `marco@ajaia.test` (local development password: `marco-demo`)

Local fallback passwords are enabled only outside production. On Render, set distinct `DEMO_ALICE_PASSWORD` and `DEMO_MARCO_PASSWORD` values of at least 16 characters, and keep them private. Render generates `SESSION_SECRET` through the blueprint setup. Production refuses to start if these secrets are missing or too short.

Login creates an eight-hour signed, HttpOnly, Secure-in-production, SameSite=Strict cookie. Protected APIs derive identity from that signed cookie; the old `x-user-id` header is ignored. Login attempts are rate-limited, and production responses include security headers. Profile switching signs out and asks for that profile's password. Documents remain private to their owner until shared; owners can grant editor/viewer access and revoke access, while viewers cannot edit.

This is a safer demo deployment, not enterprise identity: the two accounts are configured by deployment secrets, there is no password reset or user registration, and the cookie is signed (not encrypted) and contains only an account ID. Use HTTPS and do not reuse personal passwords.

## Import Support

Use **Import a file** to create a new editable document from `.txt` or `.md` files up to 2 MB. Markdown headings and simple ordered/unordered lists retain their structure; other text becomes paragraphs. DOCX, images, and attachments are not supported.

## Checks

```sh
npm test
npm run build
```

The tests cover forged-header and tampered-cookie rejection, invalid credentials, viewer write denial, persistence after server restart, production secret enforcement, secure cookies/security headers, and Markdown structure conversion.

## Deployment

`render.yaml` describes a Render free web service with no persistent disk. During Blueprint setup, provide unique passwords for both seeded accounts; the session signing secret is generated by Render. The JSON store lives on the instance's ephemeral filesystem and may be cleared on restart or redeploy. Signed sessions do not require a separate session database, but users may need to log in again after the eight-hour expiry. Local development persists documents under `data/ajaia-data.json`. A public deployment has not been provisioned from this workspace; a deployable template is not itself a live deployment. See `SUBMISSION.md` for delivery status.

## Scope

This is a product slice, not a Google Docs replacement. It includes a single-process JSON store, password-protected seeded accounts, signed sessions, TipTap rich text, autosave, basic sharing, and text/Markdown import. It does not include user registration/password recovery, real-time simultaneous editing, comments, version history, export, DOCX conversion, or multi-instance coordination. See [ARCHITECTURE.md](ARCHITECTURE.md) for the choices and next steps, and [AI_WORKFLOW.md](AI_WORKFLOW.md) for the AI-use note.
